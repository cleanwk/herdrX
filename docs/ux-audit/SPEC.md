日期：2026-10-10。本文件为自包含交接，内含 UI/UX 对比报告、功能减法审计、28 项问题、90 条目标验收用例和可直接复制的 agent 任务。无需原聊天或附件。

**最新范围：删除新建 Agent；删除文件树与文件预览。保留终端、Space/Tab/Pane、Agent 自动识别与状态导航、设备连接和搜索。**

## Herd X 0.1.5 与 ACCM：UI / UX 深度对比报告

审计日期：2026-10-10。用途：交给 Herd X 开发者及后续实现 agent，作为下一轮界面迭代依据。

### 1. 结论与本轮方向

Herd X 0.1.5 已经完成上一轮大量功能和布局补齐，但 ACCM 在任务命名、信息主次、状态扫描、搜索稳定性、标签导航、上下文解释和细节反馈方面仍更成熟。下一轮应该学习 ACCM 的交互质量，并做功能减法。

**本轮目标：一个安静、紧凑、可靠的原生终端工作台。用户管理 Space、Tab 和 Pane，在终端里直接运行工具，通过侧栏了解 Agent 状态并快速回到工作。**

用户在本次审计中明确更新了需求，优先级高于上一轮复刻清单：

- 删除“新建 Agent”专用功能。用户直接在终端启动 CLI；保留 Agent 自动识别、列表、状态和导航。
- 删除文件预览。配套的文件树辅助区、宽窄预览模式、预览操作入口及快捷键一并退出本轮目标。
- 不按 ACCM 功能清单无脑扩张。保留高频核心行为，低频能力合并或移到次级入口。
- ACC 业务插件仍不需要。已有通用 Herdr 插件兼容性与 ACC 业务集成是两件事。

本报告只交付审计与实施规格，没有修改或发布应用。第二份《功能减法与迭代审计》给出删除范围、问题编号、任务顺序及验收场景。

### 4. 为什么 ACCM 仍明显更好用

#### 4.1 同样的会话，ACCM 更容易认出“我在做什么”

Herd X 当前 Agent 主标题直接使用 `Item.label`，其解析顺序为 `title → label → terminal_title_stripped → name → agent`。列表主标题不结合 Tab 自定义名称；Pane 顶部又优先取 `pane.agent`，进一步丢失用户命名。

ACCM 在 Agent 标题里处理 Pane 自定义名、Agent 自定义标题、Tab 自定义名、非自动生成的会话名、有效终端会话标题以及工具名回退。实际画面中，ACCM 更常展示用户可理解的任务名称；Herd X 则出现多个 `codex`、启动命令和 `codex resume`，需要再读 Space 才能辨认。这里存在显示策略差异，不应简单归因于字体或数据缺失。

**学习目标：** 标题首先回答“这是哪件工作”，工具类型放第二行。同一 Pane 的侧栏、搜索、Tab 上下文、关闭确认和顶部标题使用同一个解析结果。没有真实任务标题时诚实回退，不从终端内容猜造名称。

证据：R；Herd X `Core/Sources/HerdCore/Session.swift:21`、`App/Objects.swift:5`、`App/Workbench.swift:148`；ACCM `AppModel.AgentEntry.title`、`AgentInfo.resolvedTitle`。

#### 4.2 ACCM 把第一行留给任务，Herd X 把状态挤在标题旁

ACCM Agent 行第一行是任务名与小状态点，第二行才是工具、所属 Space、必要时的设备和状态文字。Herd X 第一行左侧放状态点、右侧再放状态文字，主标题同时被两边挤压；第二行又串接工具、Space、设备。

在 260pt 侧栏、长中文任务名、全部设备视角下，Herd X 更容易出现“标题没看全，归属也没看全”。这并不要求更宽的侧栏或更大的卡片，而是需要重新分配信息优先级。

**学习目标：** 第一行 `任务名 …… 状态点`，第二行 `工具图标 工具 · Space [设备] …… 状态文字`。状态文字使用语义色并保留文字与形状，任务标题获得最高布局优先级。选中背景、鼠标悬停、运行状态、未读各有单独语义。

不要通过隐藏“等待输入”来换取视觉整洁；真正该减少的是重复信息、无意义命令名和始终出现的低价值字段。

#### 4.3 Space 的目录/分支语义应放在次级行

ACCM 的 Space 名字位于稳定文本列，目录/分支图标与对应第二行文案绑定。Herd X 每个 Space 都在两行左边放同一个 folder 图标，分支名仍只是灰色文字。

建议照 ACCM 调整为第二行目录图标或分支图标，既减少一级行装饰，又使分支信息容易理解。保留第二行高度，未知、加载失败、非 Git 目录分别表达；不能把 Git 查询失败一律画成“目录”。

#### 4.4 ACCM 的主操作更克制

当前两套界面已有类似窗口骨架，但 Herd X 使用大量 `.borderless` 系统强调色按钮，新增菜单、快速 Space、搜索、设置、标签加号等一起发蓝；ACCM 主工作区更多使用中性色图标，强调色集中于选中项、焦点与状态。

这是注意力分配问题，不是“蓝色不好看”。建议沿用 ACCM 的层级：常驻导航图标使用次级中性色，hover 才提亮；确认提交的主按钮可以强调；终端焦点边框和被选中的导航项保留强调色。终端内部 ANSI 内容保持工具原样。

本轮 ACCM 画面使用用户的浅色 Catppuccin 和自选字体，Herd X 使用默认跟随系统、SF Mono。不能把两张不同设置的截图当作同主题像素对比，也不能把 ACCM 的用户偏好写成新安装默认值。

#### 4.5 ACCM 的搜索更像稳定的导航工具

| 细节       | ACCM                                 | Herd X 0.1.5                                | 目标                       |
| ---------- | ------------------------------------ | ------------------------------------------- | -------------------------- |
| 输入区     | 一体化搜索图标、输入、分隔线         | 单独圆角 TextField 放入44pt区域             | 学习 ACCM，减少套框感      |
| 无结果     | 紧凑空态，结果区按内容变化           | 固定320pt结果区，即使无结果                 | 无结果不留下大块空白       |
| 结果类型   | Agent 工具标识、状态、必要的设备信息 | Pane 通常都用 terminal 图标                 | 快速辨认对象和待处理状态   |
| 次级信息   | 明确字段与独立设备信息               | 串接字段，会出现 `设备 ·  · `               | 过滤空值，优先身份区分字段 |
| 鼠标 hover | 最小滚动以保持可见                   | index 变化总是居中滚动                      | hover 不主动移动列表       |
| 结果更新   | 结果/高亮一起更新并约束索引          | query 变化重置index，外部结果更新无同等钳制 | 用稳定对象ID保持高亮       |
| 跨设备跳转 | 必要时清除冲突的设备筛选             | 全局搜索但 jump 不同步 deviceFilter         | 目标跳转后侧栏应可定位     |

搜索保留。它是大量 Space、Agent 下的高频导航，不属于本轮应删除的功能。

#### 4.6 Tab 看起来接近了，但操作后仍应看得见

ACCM 在选中 Tab 改变时会主动滚动到目标。Herd X AppKit Strip 创建了横向滚动容器，但更新选中项时没有滚动可见性处理；拖动也没有边缘自动滚动。较多 Tab 时，快捷键切换或新建得到的选中项可能位于可视区域外。

ACCM 还提供多 Pane 数量提示与 Tab 双击重命名；Herd X 目前只有文本、tooltip、右键重命名/关闭。建议补齐这些低成本、高辨识度细节，而不是新增标签分组、颜色体系或固定标签等功能。

#### 4.7 Pane 的标题、焦点和窗角需要收尾

ACCM 主标题与所属 Space 副标题分开呈现：主标题等宽、聚焦时强调；副标题较弱，可在中间截断。Herd X 把全部上下文拼成一个等宽、同色字符串；本机命名会话省略设备字段，多个本机会话时仍有歧义。

Herd X Pane frame 始终为矩形；ACCM 在较新 macOS 上让窗口外缘底角随窗口曲率变化，内部拆分边保持直角。可作为最终 polish，但优先级低于标题语义和焦点归属。

更需要先检查的是 `Canvas.layout()` 每次布局都把 firstResponder 设回当前终端的行为。它能方便输入，但可能抢走侧栏或其他控件的键盘焦点。此项目前是源码确认的风险路径，不能写成已经实测发生的焦点事故。

#### 4.8 状态必须与它描述的对象相邻

Herd X 底部设备选择器旁的连接点取当前选中设备；当前是独立 Shell 时无设备就显示绿色。选择器文字却可能是“所有设备”或另一个筛选设备，因此绿点容易被解读为“全部设备正常”。ACCM 的设备标题和设备上下文表达更直接。

建议每个设备分组标题旁展示自己的连接状态；底部筛选器只表达筛选范围。独立 Shell 不伪装成某个 Herdr 服务已连接。离线快照保留时明确标记“连接中断，显示上次结果”。

#### 4.9 设置页的数量与质量都要收敛

Herd X 当前设置有九个一级项。新建 Agent 删除后，十种工具的命令覆盖长表单失去核心用途，不应该因为已经实现就保留。附件能力的配置有独立消费者，删除时应拆开判断，不能连带让粘贴报错。

现有插件页与其他 grouped Form 的内边距明显不一致：顶部设备控件贴近详情区左边，底部说明也贴边；运行画面还出现中文页面里的 `Enabled` 和 `Choose a Herdr plugin.`。这是需要处理的完整性问题，不能靠换主题掩盖。

建议保留外观、终端、连接三类主要设置；通知合并到常规或行为区；Tailcat 放连接的高级类型；更新/关于合为低频页；通用插件管理作为高级入口。此分类是本轮推荐，不要求为了页数好看而改变凭据、更新渠道和插件生命周期。

#### 4.10 已决定删除的能力，不再进入精修任务

文件区和新建 Agent 在上一轮被要求补齐，但用户本轮已改变产品判断。它们即使存在布局、错误反馈或加载体验问题，也不应再投入补齐宽窄模式、预览格式、工具启动表单。

文件管理独立于文件预览。它存在真实“新路径+旧列表”的问题。如果保留单文件传输，先修复对象一致性，再把入口降到设备上下文；如果决定整体移除传输 UI，则删除该 UI 对应的修复任务，保留仍被附件消费的底层能力即可。不能为了消除审计问题而扩张新的文件管理产品。

### 4. 审计问题与明确修复要求

优先级：P1影响核心任务、对象准确性或可能中断工作；P2明显交互摩擦；P3视觉收尾。未发现经本轮验证的P0。下面的V项必须先复现，再按结果修复或关闭；禁止把风险描述写成用户已丢失数据。

#### UX01 · P1 · 任务标题不能稳定表达用户命名 [R/S]

**场景与影响：** 多个相同工具在不同任务中运行，列表出现重复工具名/启动命令，无法直接找到自己命名的任务。

**原因位置：** `Core/.../Session.swift:21`统一Item优先取title；`Workbench.swift:148`直接显示pane.label；未合并Tab自定义名。ACCM使用`AgentEntry.title`与`AgentInfo.resolvedTitle`。

**修改：** 建立纯展示投影。推荐优先级为Pane显式自定义名→Agent显式自定义标题→有效Tab自定义名→有效会话名/会话标题→工具名。区分服务端原始title、用户label、通用CLI标题；不要把所有非空title视为人工命名。根据实际RPC字段取值，缺字段则保守回退。

**验收：** 中文重命名后侧栏/搜索/Pane/关闭确认一致；状态刷新、OSC标题变化不覆盖人工名称；空白标题不形成空行。字段合同通过匿名快照fixture验证。

#### UX02 · P2 · Agent行的信息层级与ACCM有明显差距 [R/S]

**位置：** `Workbench.swift:145–151`。状态点在左，状态字在首行右，主标题可用宽度被压缩；metadata把多个值拼成10pt字符串。

**修改：** 第一行任务名+右侧小状态点；第二行工具+Space+必要设备+状态文字。常用状态文字采用语义色，不依赖颜色辨识。无真实metadata不显示占位；不为quota新增仪表盘。长metadata放tooltip或对象详情，不挤满列表。

**验收：** 200/260/480pt侧栏下长中文标题优先保留；状态字不被截成无意义单字；working、blocked、done未读、done已读、idle、unknown均可区分。是否是当前选中项与是否未读分别可见。

#### UX03 · P2 · Agent长标题缺少完整上下文入口 [R/S]

**位置：** Agent行没有Space行那样的`.help`或对象菜单；ACCM提供完整标题/目录tooltip、重命名和对象操作。

**修改：** 增加完整任务名、设备/命名会话、Space、cwd的tooltip；当前行右键提供最小的重命名、复制目录、关闭对象入口。菜单严格绑定被点击对象，不先跳转另一个工作终端。

**验收：** 选中A右键B，所有文案和动作作用于B；取消不改变A的焦点；缺cwd时“复制目录”禁用并说明，不允许无反馈空操作。

#### UX04 · P2 · Space目录/分支图标与语义分离 [R/S]

**位置：** `Workbench.swift:115–122`。左侧统一folder，第二行只写分支；加载未完成时为单个空格。

**修改：** 学ACCM把目录/分支图标放在次级行，并保留稳定行高。区分“读取中”“非Git目录”“读取失败”；失败保留最近有效分支并标旧，不能伪称无分支。

**验收：** 长分支中间/尾部截断策略一致，完整值可取；git查询慢或失败时任务名不跳位；30秒缓存不导致目录切换后显示旧路径的分支。

#### UX05 · P1 · 底部连接点和设备筛选不是同一对象 [R/S]

**位置：** `Workbench.swift:32–35`。颜色基于currentDevice，Picker基于deviceFilter；独立Shell时回退绿色。

**修改：** 连接状态移到所属设备分组；底部只表示筛选范围。若保留汇总标记，必须按范围聚合并有可读说明，不能默认绿。

**验收：** A在线/B离线、全部设备、仅B、当前为独立Shell四种状态均不产生“全部在线”的假象；颜色外有文本或AX状态。

#### UX06 · P1 · 创建Space的目标来源不统一 [S/V]

**位置：** 空设备组的“Create Space…”只把newSpace设为true（`Workbench.swift:138`），表单初始化却从selectedDevice/首个在线设备选择；`Desk.quickSpace:522`也没有以筛选器作为明确目标。

**风险：** 点击B设备下的创建入口，表单可能预选A；当前独立Shell且筛选远端时快速创建可能落到其他设备。未在用户环境执行创建来复现。

**修改：** 创建意图携带显式DeviceID和cwd来源，组内操作总是组内设备；全局入口使用当前明确上下文，无法确定时要求选择。不要静默选择“第一个在线设备”。快速按钮tooltip显示目标。

**验收：** 两设备具有相同Space/Pane ID，分别从组内、当前工作区、设备筛选、独立Shell入口创建；只在预期设备新增一次；禁用与错误都指向同一对象。

#### UX07 · P1 · 全局搜索跳转后侧栏可能仍被旧设备筛选隐藏 [S/V]

**位置：** `Desk.reindex:463`索引所有设备；`jump:485`只select、不更新deviceFilter。

**修改：** 延续全局搜索，并明确“全部设备”语义。命中筛选外对象后清除冲突筛选或切换到目标范围，同时展开必要分组、滚到目标行。ACCM已有清除冲突筛选的行为可参考。

**验收：** 筛选A，搜索并打开B：终端属于B，侧栏可看到B的选中对象，下一次创建/关闭也属于B；取消搜索不改变原范围。

#### UX08 · P2 · 选中Tab未保证可见，溢出导航不完整 [S]

**位置：** `Tabs.swift:12–17,78–86`。更新selection不scrollRectToVisible；拖动没有边缘自动滚动。

**修改：** 仅在选中目标不可见时最小滚动；新增、快捷键、搜索跳转、关闭后回落全部复用。拖至边缘时可逐步横滚，并提供非拖拽的移动入口或键盘替代。

**验收：** 12个长Tab，⌘9/前后切换/创建/关闭当前Tab之后都能看到完整选中态；拖动边缘可到首尾；不把后台标题刷新变成自动滚动。

#### UX09 · P2 · Tab缺少多Pane提示和熟悉的重命名细节 [S]

**位置：** `Tabs`的entries只有ID与字符串；右键可rename，鼠标事件不处理双击；ACCM显示paneCount并支持双击。

**修改：** 标题后只在Pane数量>1时显示弱化数字；双击Tab进入重命名，Enter提交、Esc取消；空名称行内提示，不静默丢弃。不要加新的复杂标签管理功能。

**验收：** 1→2→1 Pane数量及时变化且不闪烁；长Tab中数字仍可辨；双击不误触拖动、不创建终端。

#### UX10 · P1 · 搜索高亮由数组下标维持，实时更新可能改变Enter目标 [S/V]

### 6. 交互状态合同

#### 6.1 四种状态不能相互替代

| 状态轴 | 用户问题                   | 展示规则                                       |
| ------ | -------------------------- | ---------------------------------------------- |
| 选中   | 我正在看哪一个？           | 行背景/字体权重、Tab选中、Pane焦点             |
| 运行   | 这个Agent正在做什么？      | working/blocked/done/idle/unknown的文字+小形状 |
| 未读   | 是否有我没看过的完成结果？ | 独立完成未读标识，不能把所有done画成未读       |
| 连接   | 这些数据和输入是否仍有效？ | 所属设备状态、旧快照标识、重连/恢复入口        |

保留既有注意力合同：列表排序blocked→working→done→idle→unknown；Space聚合blocked→未读done→working→无提示；首次快照done不造未读；非done→done产生未读；离开正在查看的行再清理对应未读；离开done或对象删除清理。⌘⇧J只在blocked与未读done间导航。通知开关不能改变这些规则。

#### 6.2 选择与焦点

点击Space、Tab、Agent是明确导航意图，可以进入相应终端。仅刷新状态、打开右键菜单、hover、切设置、调整侧栏宽度不是终端输入焦点转移意图。打开搜索后输入只进入搜索；Esc恢复原有效焦点；目标被删除时选择明确的相邻有效对象或空态，不跳到另一个设备的同名对象。

键盘顺序应按工作区域可理解地移动。装饰图标不独立占焦点。保留当前Tab的Pane焦点记忆；关闭/移动该Pane后记忆要被校正。

#### 6.3 加载、空、失败与旧数据

初次无数据可显示紧凑loading；刷新保留现有内容和滚动位置。真正空列表说明“没有Space/没有Agent”；请求失败说明“未能刷新”，保留最近有效内容并标旧。写操作提供忙态防重复，失败在相关对象附近给恢复动作；全局alert用于需要用户决策的操作，不用于每次普通刷新失败。

#### 6.4 关闭行为

Sheet在前时⌘W只关闭/请求取消该Sheet；重命名未保存则按其取消规则处理。工作台⌘W针对当前Pane；服务器关闭明确终止进程，断开客户端不终止服务端。独立Shell有前台任务时提示，空闲时可直接关闭。关闭Tab说明包含的Pane数量。取消必须零写入、零信号、零焦点跳转。

#### 6.5 空间不足

最低工作台980×620pt、侧栏200/260/480pt都要检查。删除文件区后无需为文件宽度保留空间。多层分屏不能只按10%比例生成几乎不可操作的Pane：根据终端最小可用字符网格限制分屏/缩放，无法再拆时禁用并解释。不要通过把字体不断缩小解决拥挤。

#### 6.6 主题和反馈

改主题/字体不重建PTY或丢历史。浅/深、系统切换、选中/hover/非key状态分别验收。复制等成功反馈短暂、靠近操作，不弹阻断alert；失败反馈持久到用户理解或恢复。仅在明确必要处动画，系统减少动态效果打开时仍完整可用。
